# 할 일 동기화 (비공개 GitHub 저장소) — 설계

작성일: 2026-10-02 · 상태: 사용자 검토 대기 · 대상: 할 일 앱 `C:\eduReact`(배포 https://polos0117.github.io/eduReact/)

## 1. 목적

지금은 할 일이 브라우저의 localStorage 에만 있어서 PC·휴대폰·브라우저마다 데이터가 다르다.
**내보내기를 누르지 않아도** 바꿀 때마다 비공개 GitHub 저장소의 JSON 파일에 저장하고, 모든 기기가 그 파일을 바라보게 한다.
서버는 두지 않는다 — 앱(정적 페이지)이 GitHub API 를 직접 부른다. 실시간은 아니고 수 초~1분 안에 맞춰진다(사용자가 결과를 보고 실시간 DB 로 옮길지 정한다).

### 성공 기준

- PC 에서 할 일을 고치면, 휴대폰에서 앱을 열거나 탭으로 돌아오면(또는 열어 둔 채 1분 안에) 같은 내용이 보인다.
- 두 기기에서 서로 다른 할 일을 고쳐도 둘 다 살아남는다. 한쪽에서 지운 할 일이 다른 기기에서 되살아나지 않는다.
- 인터넷이 끊겨도 앱은 지금처럼 쓰이고, 다시 연결되면 맞춰진다.
- 동기화를 켜지 않은 사람에겐 지금과 똑같이 동작한다(동기화는 선택).
- 새 런타임 의존성 0개.

### 범위 밖 (1차)

실시간 반영, 여러 사람 공유, 스킨·정렬·태그 색·보고서 템플릿 같은 화면 설정 동기화, 저장소 기록에서 되돌리기 화면(GitHub 웹에서 직접), OAuth 로그인.

## 2. 설정 (기기마다 한 번)

- 사용자가 GitHub 에 **비공개 저장소**(예: `polos0117/todo-data`)를 만들고, **Fine-grained token** 을 만든다:
  저장소 접근 = 그 저장소 하나, 권한 = Contents 읽기·쓰기. 앱 설정 화면에 만드는 순서를 짧게 안내하고 GitHub 토큰 만들기 페이지 링크를 둔다.
- 설정 창에 **동기화** 칸: 저장소(`소유자/이름`), 파일 경로(기본 `todos.json`), 토큰(비밀번호 칸), 기기 이름(기본 "PC"/"휴대폰" 추측, 커밋 메시지용), [연결] · [끊기].
- [연결] 을 누르면 저장소 접근을 확인하고(실패하면 이유: 토큰이 틀림/권한 없음/저장소 없음), 곧바로 첫 동기화.
- 설정은 그 기기의 localStorage(`sync`)에만 저장한다. 토큰은 화면에 다시 보이지 않는다(가린 채 "저장됨").

## 3. 동기화

### 시점

- **올리기**: 할 일이 바뀌면 3초 동안 더 바뀌지 않을 때 동기화(받기 → 합치기 → 올리기).
- **받기**: 앱을 열 때, 탭이 다시 보일 때(`visibilitychange`), 열어 둔 동안 60초마다, 인터넷이 다시 연결될 때(`online`).
- 한 번에 하나만 돈다. 도는 중에 또 바뀌면 끝난 뒤 한 번 더.

### 파일

- 저장소의 `todos.json` = `{ "version": 1, "todos": [...] }` (할 일 앱 내보내기와 같은 할 일 모양, 사람이 읽기 좋게 들여쓰기).
- GitHub Contents API: `GET /repos/{owner}/{repo}/contents/{path}` 로 내용(base64)과 `sha`, `PUT` 으로 `sha` 를 붙여 저장 → 커밋 하나. 커밋 메시지 `할 일 동기화 (PC)`.
- 한글이 깨지지 않게 UTF-8 ↔ base64 변환(`TextEncoder`/`TextDecoder`).
- 받은 내용은 앱의 `normalizeTodo` 로 검증한다(가져오기와 같은 규칙). 깨진 파일이면 덮어쓰지 않고 오류 표시.

### 합치기 (3-way)

기기마다 **마지막으로 동기화에 성공한 할 일 목록(base)** 을 localStorage(`sync-base`)에 둔다. 동기화 때 `merge(base, local, remote)`:

| base | local | remote | 결과 |
|---|---|---|---|
| 없음 | 있음 | 없음 | local (이 기기에서 새로 만듦) |
| 없음 | 없음 | 있음 | remote (다른 기기에서 새로 만듦) |
| 없음 | 있음 | 있음 | 같으면 그대로, 다르면 local |
| 있음 | 같음 | 바뀜 | remote |
| 있음 | 바뀜 | 같음 | local |
| 있음 | 바뀜 | 바뀜 | local (같은 할 일을 양쪽에서 고침 — 지금 기기가 이긴다) |
| 있음 | 없음 | 같음 | 지움 (이 기기에서 지움) |
| 있음 | 같음 | 없음 | 지움 (다른 기기에서 지움) |
| 있음 | 없음 | 바뀜 | remote (지웠지만 다른 기기에서 고침 — 되살린다, 잃지 않게) |
| 있음 | 바뀜 | 없음 | local (위와 같은 이유) |
| 있음 | 없음 | 없음 | 지움 |

- "같음/바뀜" 은 할 일 객체 전체 비교(키 순서 무관).
- **순서**: 이 기기의 순서(공통 할 일 기준)가 base 와 다르면 이 기기 순서, 아니면 remote 순서. 한쪽에만 있는 새 할 일은 그쪽 목록의 앞뒤 이웃을 따라 끼워 넣고, 못 찾으면 끝에.
- 첫 연결(base 없음): 양쪽 합집합 — 아무것도 버리지 않는다.
- 합친 결과를 앱 상태로 바꾸고(이 기기의 화면이 다른 기기 내용으로 바뀜), remote 와 다르면 올린다. 올리기에 성공하면 그 결과가 새 base.
- 올리기가 `409`/`422`(sha 가 바뀜 — 그새 다른 기기가 올림)로 거절되면 다시 받아 합쳐 한 번 더(최대 3번).

### 상태 표시

머리글 날짜 줄 옆에 작은 글: `동기화됨 · 2분 전` / `동기화 중…` / `오프라인 — 연결되면 올려요` / `토큰을 확인해 주세요`(401·403) / `저장소를 찾지 못했어요`(404) / `동기화 오류 — 다시 시도해요`. 누르면 설정의 동기화 칸이 열린다. 동기화를 켜지 않았으면 아무것도 안 보인다.

## 4. 구성

```
src/lib/merge.js        merge(base, local, remote) → { todos, changedLocal, changedRemote }  (순수)
src/lib/github.js       createClient({ repo, path, token, fetch }) → { read(), write(todos, sha, message) } , base64 UTF-8 변환
src/lib/syncEngine.js   한 번의 동기화: 받기 → 합치기 → 올리기(재시도) — 의존성(client, 상태 읽기/쓰기, base 저장)을 받아서 순수하게 테스트
src/hooks/useSync.js    시점(디바운스·주기·visibility·online), 상태 글, 엔진 호출, 앱 상태 바꾸기(usePersistedReducer 의 REPLACE)
src/components/Settings.jsx  동기화 칸 추가
src/App.jsx             useSync 연결, 머리글 상태 글
```

- `usePersistedReducer` 의 `REPLACE` 를 내보내 동기화 결과로 상태를 통째로 바꾼다(지금도 다른 탭 변경에 쓰는 길).
- localStorage 저장(지금 동작)은 그대로 — 동기화는 그 위에 얹는다.
- 토큰은 그 기기 브라우저에만 있다. 앱은 할 일 글을 `innerHTML` 로 넣지 않으므로(지금도) 토큰을 빼 갈 길이 없다.

## 5. 테스트

- `merge.js`(Vitest): 표의 모든 줄, 첫 연결 합집합, 순서(이 기기에서 바꿈/remote 에서 바꿈/새 항목 끼워 넣기), 키 순서만 다른 객체는 같음, 결과 플래그.
- `github.js`: 가짜 `fetch` 로 GET/PUT 요청 모양(주소·헤더·본문), 한글 왕복, 404(파일 없음) → 빈 상태, 401/403/404/409/422 → 오류 종류.
- `syncEngine.js`: 가짜 client 로 첫 연결(파일 없음 → 만들기), 받기만(로컬 변화 없음 → 올리지 않음), 409 재시도 후 성공, 3번 실패 → 오류, 깨진 원격 파일 → 덮어쓰지 않음.
- 화면: headless Chrome 에서 GitHub API 를 가로채는 가짜 서버(`Fetch.requestPaused`)로 두 기기(사용자 폴더 둘)를 흉내 — A 에서 추가·완료·삭제 → B 에서 반영, 동시에 다른 항목 수정 → 둘 다 남음, 오프라인 → 다시 연결 시 올림, 상태 글.
- 마지막으로 사용자가 실제 저장소·토큰으로 PC·휴대폰에서 확인.
